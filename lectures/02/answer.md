## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：学習率 `lr` を 2e-4 → 2e-3（10 倍）に変更。他の設定は同じ。変更後はセッションを再起動して上から実行した。
- 結果（比較表や数字）：

  |                                                              | lr = 2e-4（元）                | lr = 2e-3（10 倍）             |
  | ------------------------------------------------------------ | ------------------------------ | ------------------------------ |
  | Training Loss（step 10 / 20 / 30 / 40）                      | 1.570 / 0.086 / 0.019 / 0.0141 | 0.951 / 0.109 / 0.022 / 0.0137 |
  | 最終 loss                                                    | 0.0141                         | 0.0137                         |
  | 学習時間                                                     | 73 秒                          | 72 秒                          |
  | 学習後 `format_rate`                                         | 1.000（21/21）                 | 0.952（20/21）                 |
  | 学習後 `content_rate`                                        | 0.905（19/21）                 | 0.714（15/21）                 |
  | セクション 6 で needs_review と答えた数（FAQ に無い 3 問中） | 2                              | 0                              |
  - loss：学習率を上げると序盤（step 10）は速く下がったが、step 20・30 では元の設定のほうが低くなり、最終的にはほぼ同じ値になった。
  - 評価：形式は 1 問だけ崩れ、内容の正解は 4 問減った。
  - セクション 6：lr = 2e-3 では 4 問すべてに「課題の提出期限は 9 月 30 日 23:59（日本時間）です。」と同じ文で答えた。対照の「課題の提出期限」では正解だが、FAQ に無い 3 問にも同じ文で断定しており、「担当教員の名前」のような無関係な質問にも締切を答えている。
  - 考察：学習データに対するlossはほぼ同じなので、学習データへの当てはまりには差がない。それでも評価の成績が下がったのは、汎化が悪くなったためと考える。学習率が大きいと1回の更新でパラメータが大きく動くため、元のモデルが持っていた「質問の中身を読み分ける力」が崩れ、学習データで覚えた答えの1つを使い回すようになったと考えられる。
  - 限界：各設定1回ずつの実行であり、GPU上の学習はseedを固定しても完全には再現しない。また評価は21問なので、1問で約0.05変わる。ただし無関係な質問にもすべて同じ答えを返すという失敗の型は偶然では説明しにくい。

- ファインチューニングが向く場面・向かない場面についての考察：
  - 向く場面：出力の形式・口調・決まった型をそろえたいとき。今回もJSON形式は14件・数分の学習で身についた。
  - 向かない場面：「どの情報に根拠があるか」を正しく判断させたいときや、締切などの事実が変わりうる知識を扱うとき。学習後のモデルは学習データと似た質問に根拠なく断定し、学習率を上げるとその傾向が強まった。こうした場面では、FAQや資料を検索して根拠を示す方法と組み合わせるほうが向いていると考える。
